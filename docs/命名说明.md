# 命名说明

## 定名

| 用途 | 名称 |
|---|---|
| 项目名 / 窗口标题 | **帕米尔冰湖档案** |
| 软件全称（软著申报） | 帕米尔高原冰湖识别与风险评估软件 V1.0 |
| 简称 | 冰湖档案 / PamirLake |
| 可执行文件 | `PamirLake.exe` |

## 为什么叫"档案"而不是"预警"

这是全项目最重要的一处用词取舍，答辩时会被追问，先说清楚。

**"预警"（early warning）是一套有明确内涵的系统**：准实时监测 → 阈值触发 →
通信链路 → 下游响应。它要求端到端可用，任何一环断了都不叫预警。

本项目是离线桌面软件，跑的是历史影像与年际时序，输出的是"这个湖当前
处什么风险状态、依据是哪几条判据"。它**不**具备实时性，也**不**接下游响应。
叫"预警"属于承诺了做不到的事，评委里只要有做灾害的，一句话就能问穿。

**"档案"对应的是系统真实做的事**：每个湖一条记录，包含：

- 面积时序（逐年/逐期，含每期用的哪景影像、云量多少）
- 每个判据的实测值、阈值、命中与否
- 数据缺口如实标注（UNKNOWN 而不是 LOW）
- 阈值 ±20% 敏感性：结论在多大程度上依赖阈值精调

这套东西的价值不在"提前几分钟报警"，而在**可复现、可审计、可被独立验算**。
评委拿任何一年的影像自己跑一遍，应当得到同一个数——这是现有 GLOF 研究里
最缺的一环，也是本项目的真正立足点。

## 名称的四个约束

起名时按这四条筛的：

1. **地名要准**。研究区是塔什库尔干县的两块：西部帕米尔（慕士塔格/公格尔，
   4 个湖、零溃决记录）与东部喀喇昆仑克勒青河（4 个冰坝湖、38 次溃决记录，
   Kyagar 一个湖占 34 次）。两块行政上同属塔县，统称"帕米尔"成立。
   不用"克亚吉尔"——那是一个湖，不是系统。
2. **不夸大**。见上一节。
3. **能申报**。软著全称要能一眼看懂是做什么的，不能只有品牌名。
4. **窗口标题要短**。Qt 窗口标题栏放不下长名字，"帕米尔冰湖档案"七个字正好。

## 备选方案与落选原因

| 备选 | 优点 | 为什么没选 |
|---|---|---|
| 溢流线 | 学科上最精准（冰坝湖溃决的物理条件就是水位到溢流口，现有判据"面积/平台比值 0.95"本质就是离溢流线多远） | 需要一句话解释，窗口标题也偏长 |
| 冰鉴 | 短、有辨识度 | 用典较深，评委不一定第一时间理解 |
| 帕米尔冰湖风险筛查系统 | 最直白，审核最顺 | 没有记忆点，放在一堆参赛项目里认不出来 |

"溢流线"在答辩时可以作为**一句话解释**使用：
> 我们给每个冰坝湖算的是它离溢流线还有多远——面积逼近平台值，
> 就说明快蓄满了。

## 代码里的落点

改名只动了展示层，包名 `glof`、模块名、CLI 命令 `python -m glof.cli` 均未变，
避免破坏已有的 170+ 条断言和外部调用。

- `glof/ui/qml/Main.qml` — `title`
- `glof/ui/__main__.py` — `argparse` 的 `description`
- `scripts/capture_gui.py` — 截图时按标题找窗口
- `README.md` — 标题与开篇
